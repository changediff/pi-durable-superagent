# A2A (agent-to-agent)

The superagent is callable by, and can call, other agents over A2A JSON-RPC. This is how cc2 Hermes,
deb01 Hermes and CowAgent (汤圆, deb02) hand work to it and read the answer back.

A2A ships **inside the plugin** (`src/plugin/tools.ts` + `src/pi/a2a.ts` server,
`src/pi/a2a-client.ts` client) — there is no separate service and no extra process.

## Server

| Item | Value |
|---|---|
| Bind | `0.0.0.0:18802` inside the container, published as `100.68.159.13:18802` (tailnet only) |
| Card | `GET /.well-known/agent-card.json` (also `/agent.json`) — name `cc2-pi` |
| RPC | `POST /` or `POST /a2a/v1` |
| Methods | `SendMessage` (legacy alias `message/send`), `GetTask` (alias `tasks/get`) |
| Auth | `Authorization: Bearer $SUP_A2A_TOKEN`; a request without it gets `-32050` |
| URL in card | `SUP_A2A_PUBLIC_URL` — must be the address callers can actually reach |

Semantics worth knowing:

- A **reply** resolves the `SendMessage` HTTP response with the final text.
- An **acknowledgement / notice** does *not* resolve it: the task moves to `TASK_STATE_WORKING` and the
  caller keeps waiting (up to `SUP_A2A_WAIT_MS`), or polls `tasks/get` by task id.
- The A2A `contextId` becomes the Thread id, so follow-ups that reuse a contextId land in the same
  Thread and hit the **fast path** (see 003-execution.md). Omitting it mints a one-shot `ctx-<uuid>`.

## Configuration

| Key | Default | Meaning |
|---|---|---|
| `SUP_A2A` | off | set to `1` to start the server |
| `SUP_A2A_PORT` | `18802` | listen port |
| `SUP_A2A_TOKEN` | empty | bearer token; **empty accepts anyone** — always set it |
| `SUP_A2A_PUBLIC_URL` | `http://cc2.pig-bowfin.ts.net:<port>` | URL published in the card |
| `SUP_A2A_WAIT_MS` | `100000` | how long one inbound `SendMessage` waits for the final reply |
| `SUP_A2A_PEERS` | `[]` | JSON array of outbound peers: `{name, url, token, timeout}` |

`SUP_A2A_PEERS` is parsed as JSON; a malformed value yields **no peers** instead of failing startup —
so an empty peer list in the logs means "check the JSON", not "peer is down".

## Peer side

**Hermes (cc2 `100.104.200.115`, deb01).** Each host has `a2a_agents:` in its config
(`/root/.hermes/config.yaml` on cc2, `/home/hermes/.hermes/config.yaml` on deb01):

```yaml
a2a_agents:
  cc2-pi:
    url: http://cc2.pig-bowfin.ts.net:18802
    auth:
      type: bearer
      token: <SUP_A2A_TOKEN>
    timeout: 120
```

**CowAgent (deb02).** Its A2A facade on `18789` is **inbound only**, so the outbound direction uses a
small client script shipped with the agent workspace:

```bash
# as cow on deb02
python3 /home/cow/cow/scripts/a2a_send.py --list
python3 /home/cow/cow/scripts/a2a_send.py cc2-pi "把这句话交给 pi"
```

Peers for that script live in `/home/cow/cow-a2a/peers.json` (0600, owned by `cow`).

## Operations

```bash
# health: card + unauthenticated rejection
curl -s http://cc2.pig-bowfin.ts.net:18802/.well-known/agent-card.json | head -c 200
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://cc2.pig-bowfin.ts.net:18802/ -d '{}'

# one real round-trip through the container
TOK=$(grep -o 'SUP_A2A_TOKEN=[^ ]*' <(docker inspect pi-agent --format '{{.Config.Env}}'))
curl -s -X POST http://100.68.159.13:18802/ -H "Authorization: Bearer ${TOK#*=}" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":"1","method":"SendMessage","params":{"message":{"role":"ROLE_USER","messageId":"m1","parts":[{"kind":"text","text":"只回 PONG"}]}}}'
```

Adding a peer: append to `SUP_A2A_PEERS` in `/etc/piagent.env`, recreate the container
(`bash deploy/docker-run.sh`), then confirm with a task that calls `a2a_send` for that name.

Rotating the token: change `SUP_A2A_TOKEN` in `/etc/piagent.env`, recreate the container, and update
`a2a_agents.cc2-pi.auth.token` on cc2 **and** deb01 plus `peers.json` on deb02.

## Limits

- The endpoint is reachable **only over Tailscale** (published on the tailnet IP, not `0.0.0.0` on the host).
  Do not re-publish it publicly; the token is the only other control.
- No streaming (`capabilities.streaming: false`): a call returns one final text.
- A long task can outlive `SUP_A2A_WAIT_MS`; the caller then gets the working notice and must poll
  `tasks/get` with the task id.
- Peer discovery is best-effort, not cached: a changed peer URL is picked up on the next call.
